# Skill_Fusion
Skill Fusion AI turns any combination of skills you choose into a market-scored learning roadmap, a real project, and a ready resume — powered by a fully self-hosted AI stack.

## Project status

This is a capstone project under active development. The table below reflects what's actually wired to a real backend versus what's still frontend-only demo data.

### Built end-to-end (real backend + tests)

- **Authentication** — register, login, JWT access token + httpOnly refresh cookie, logout, password reset, email verification.
- **GitHub OAuth connect** — a logged-in user can connect their real GitHub account (`repo` scope). The connection is verified by GitHub, not a free-text field, and the access token is never returned by the API.
- **Growth Log** — manual entries, credential link verification, and GitHub repo import (including private repos once connected). Entries from private repos are flagged in the UI. Verified / self-reported / pending status is rendered by one shared component (`window.LogSourceBadge`) used on both the Growth Log page and the Dashboard, so the two can't silently drift apart.
- **GitHub contribution graph** — real commit activity pulled from GitHub's GraphQL API, combined with manually logged entries into one activity heatmap.
- **Resume & Cover Letter generator** — grounded in the user's actual Growth Log entries (not invented), optionally targeted at a pasted job listing, generated via a self-hosted LLM over an OpenAI-compatible `/v1/chat/completions` endpoint. Exports to PDF server-side (`reportlab`).
- **AI Skill Fusion Engine** — pairing two skills calls the SF model for a brief, a flagship project brief, and a Fusion Score; fusions persist per-user and restore on login (`/api/fusion/`, `/api/fusion/history/`).
- **Baseline quiz** — 5 questions per skill (2 hard / 2 medium / 1 easy) generated per skill; answer keys never leave the server (`QuizSession`), scoring floors at level 1.
- **Learning Roadmap Generator** — SF generates 3 preview paths (1 shell call + 3 detail calls), previews persist as rows, choosing one locks it; ownership is enforced (403 for other users' fusions, 423 for locked plans).
- **Project Generator** — the flagship project brief is generated by SF and delivered with every fusion.
- **Fusion Score** — real pipeline: job listings ingested from AdZuna/Arbeitnow → `nomic-embed-text` embeddings → pgvector (HNSW index). Rarity = mean cosine distance over listings for the pair, demand = listing counts; scores cached 7 days with a `recompute_score_cache` management command for weekly refresh. Falls back to a labeled deterministic heuristic when fewer than 10 listings exist for the pair.
- **Explain It** — week/milestone reflections scored by SF (clarity/note/suggestion); deterministic server-side fallback when the model is unreachable. Logged entries carry a `self-reported`/verified source badge.
- **Posts** — LLM-drafted, tone-guided posts from a Growth Log entry with redraft support; throttled CRUD.

### Prototype (secondary feature)

- **Peer Connect & Open Chat** — the connection flows (lounge chat, skill exchanges, reports) are still an isolated client-side prototype in `frontend/src/app/Connect.js` + `store.js` with no backend endpoints yet. It is intentionally kept out of the persistence/model layer and is next planned backend work.

### Testing

- **Backend:** 96 Django tests across 9 apps (`authentication`, `growthlog`, `resume`, `posts`, `fusion_engine`, `roadmaps`, `projects`, `scores`, `explain`) covering auth, ownership scoping, per-feature LLM contracts (mocked LLM calls), cache TTL/recompute behavior, and the roadmap preview→choose→lock flow — all without calling the real LLM. Linted with `ruff`.
- **Frontend:** 22 Playwright end-to-end tests (landing nav, onboarding, Growth Log, app shell, resume generation) against a mocked API, no backend required to run them. Linted with `eslint`.
- **CI:** two GitHub Actions workflows (`backend-ci-pipeline.yml`, `frontend-ci-pipeline.yml`), each lint-then-test, triggered on push/PR to their own folder, with lint and coverage/test reports uploaded as artifacts.

### Known gaps

- The frontend has no build step (plain `<script>` tags + in-browser Babel), so it's only deployable as static files pointed at a running backend — not yet deployed anywhere public.
- GitHub access tokens are stored in plaintext in the database; acceptable for local development, not for production.
- The LLM endpoint (`LLM_API_URL`) is a shared dev server on a private Tailscale network — it isn't reachable from CI or from a public deployment, so the resume generator currently only works on machines with access to that network.
- No CD/deploy step yet — CI currently only lints, tests, and reports.

### Run it locally

1. **Postgres 16 with pgvector** (`CREATE EXTENSION vector;`), then configure `backend/.env` from `backend/.env.example` (SECRET_KEY, DB_*, CORS_ALLOWED_ORIGINS).
2. **Backend:** `cd backend && pip install -r requirements.txt && python manage.py migrate && python manage.py runserver 8000` (defaults are fine for local dev).
3. **Frontend:** any static server on port 3000, e.g. `cd frontend && python3 -m http.server 3000` (it reads `window.API_BASE_URL` from `index.html`, default `http://localhost:8000/api`).
4. **AI:** `LLM_API_URL` points at an OpenAI-compatible server (`/v1/chat/completions`) — locally that's `http://localhost:8081` (mlx_lm.server with the SF adapter). Without it, generation endpoints degrade to their labeled fallbacks (Explain It, Fusion Score heuristic) or return a clear 502 (Resume, Roadmaps).
